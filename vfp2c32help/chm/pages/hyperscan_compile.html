Hyperscan_compile

Compiles a regular expression into a hyperscan database.

Hyperscan_compile(@caExpressions, @nDb, naFlags, nMode[, aExtendedFlags[, oPlatform]])

Parameters

@caExpressions

A single regular expression or an array of regular expressions.

Note

If an array of multiple expression's is passed one can specify the expression match ID in the 2nd column.
When passing a 1 dimensional array the expression match ID is the row index of the array.
The expression identifier is reported back in the various Hyperscan_scan functions result cursor in the "match_id" field.

@nDb

A variable by reference in which a handle to the compiled database is returned.

naFlags (additional)

A single numeric flag value or an array by reference of flags for each regular expression used to compile the database.

FlagDescription
HS_FLAG_CASELESSThis flag sets the expression to be matched case-insensitively by default
HS_FLAG_DOTALLThis flag sets any instances of the . token to match newline characters as well as all other characters.
HS_FLAG_SINGLEMATCHThe flag is not supported, since HS_FLAG_SOM_LEFTMOST is implied for all expressions.
HS_FLAG_ALLOWEMPTYThis flag instructs the compiler to allow expressions that can match against empty buffers, such as .?, .*, (a|). Since Hyperscan can return every possible match for an expression, such expressions generally execute very slowly; the default behaviour is to return an error when an attempt to compile one is made. Using this flag will force the compiler to allow such an expression.
HS_FLAG_UTF8This flag instructs Hyperscan to treat the pattern as a sequence of UTF-8 characters. The results of scanning invalid UTF-8 sequences with a Hyperscan library that has been compiled with one or more patterns using this flag are undefined.
HS_FLAG_UCPThis flag instructs Hyperscan to use Unicode properties, rather than the default ASCII interpretations, for character mnemonics like \w and \s as well as the POSIX character classes. It is only meaningful in conjunction with HS_FLAG_UTF8.
HS_FLAG_PREFILTERThe flag is not supported, since the HS_FLAG_SOM_LEFTMOST is implied for all expressions.
HS_FLAG_COMBINATIONThis flag instructs Hyperscan to parse this expression as logical combination syntax. Logical constraints consist of operands, operators and parentheses. The operands are expression indices, and operators can be ‘!’(NOT), ‘&’(AND) or ‘|’(OR). For example: (101&102&103)|(104&!105) ((301|302)&303)&(304|305)
HS_FLAG_QUIETThis flag instructs Hyperscan to ignore match reporting for this expression. It is designed to be used on the sub-expressions in logical combinations.

Note

When passing a single numeric flag parameter it is used for all expressions passed in caExpressions.

The hyperscan flag HS_FLAG_SOM_LEFTMOST is added automatically, without this flag it would be impossible to
extract the regular expression out of the scanned data.

Copy code
LOCAL laRegs[2], laFlags[2]
m.laRegs[1]  = '^PROCEDURE\s+\w+$'
m.laRegs[1]  = '^ENDPROC\b'
m.laFlags[1] = HS_FLAG_CASELESS + HS_FLAG_MULTILINE && flags used for 1st regular expression
m.laFlags[2] = HS_FLAG_CASELESS  && flags used for 2nd regular expression
nMode (additional)

A mode to compile the regular expression.

ModeDescription
HS_MODE_BLOCK
HS_MODE_STREAM
HS_MODE_SOM_HORIZON_SMALLLimits the lookback buffer to 64 kilobytes in HS_MODE_STREAM
HS_MODE_SOM_HORIZON_MEDIUMLimits the lookback buffer to 2 gigabyte in HS_MODE_STREAM, the real
lookback capability is controlled by the buffersize passed to Hyperscan_scan / Hyperscan_scan_files / Hyperscan_scan_cursor though.

The following mode extension's control which data is reported back in the result cursor.
ModeDescription
HS_MODE_EX_MATCH_IDIncludes the "match_id" field
HS_MODE_EX_LINENOIncludes the "match_lineno" field
HS_MODE_EX_LITERALFor compiling all regular expression as literals

Note

Pass the same nMode parameter to the various Hyperscan_scan functions which was used to compile the expressions to ensure correct execution behaviour.

aExtendedFlags (optional)

An array of objects with extened flags to control the pattern matching behaviour.

Note

This array has to be passed by name, not by reference!

PropertyDescription
min_offsetThe minimum end offset in the data stream at which this expression should match successfully.
max_offsetThe maximum end offset in the data stream at which this expression should match successfully.
min_lengthThe minimum match length (from start to end) required to successfully match this expression.
edit_distanceAllow patterns to approximately match within this edit distance.
hamming_distanceAllow patterns to approximately match within this Hamming distance.
oPlatform (optional)

A platform object specifying the available CPU instruction set and a tuning value to optimize the database for
a specific CPU architecture.

If ommitted the database is optimized for the CPU it is compiled on.

Return Value

A hyperscan return code.
HS_SUCCESS (0) on success otherwise the errorcode.

Example

Copy code
LOCAL laRegs[2,2], lnRet, lnDB, lnMode
LOCAL laExtendedFlags[2], loExtFlags

m.lnDB = 0
m.laRegs[1,1] = '\bRegularExpression1\b'
m.laRegs[1,2] = 1
m.laRegs[2,1] = '\bRegularExpression2\b'
m.laRegs[2,2] = 5

m.loExtFlags = CREATEOBJECT('Empty')
ADDPROPERTY(m.loExtFlags, 'min_offset', 32)
ADDPROPERTY(m.loExtFlags, 'max_offset', 64)
m.laExtendedFlags[1] = m.loExtFlags
m.loExtFlags = CREATEOBJECT('Empty')
ADDPROPERTY(m.loExtFlags, 'min_offset', 128)
ADDPROPERTY(m.loExtFlags, 'max_offset', 256)
m.laExtendedFlags[2] = m.loExtFlags

m.lnRet = Hyperscan_compile(@m.laRegs, @m.lnDB, HS_FLAG_MULTILINE, ;
HS_MODE_STREAM + HS_MODE_SOM_HORIZON_SMALL, "laExtendedFlags")

IF m.lnRet != 0
    AERROREX('laError')
    ? laError[1], laError[2], laError[3]
ENDIF
