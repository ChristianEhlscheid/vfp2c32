Hyperscan_scan_files

Executes a hyperscan operation on a set of files.

Hyperscan_scan_files(nDb, nScratch, nMode, cnSource, cnResult[, cContextField[, nBuffersize]])

Parameters

nDb

A handle to a hyperscan database previously compiled with Hyperscan_compile.

nScratch

A handle to scratch memory previously allocated with Hyperscan_alloc_scratch.

Note

If you pass 0 the function will allocate and free the needed scratch memory internally.
If you call this function many times in succession it's more performant to manually allocate and free
the scratch memory with Hyperscan_alloc_scratch and Hyperscan_free_scratch.

nMode

The mode that was used to compile the regular expression.

cnSource

The alias or workarea number of the source cursor of files.

Note

The source cursor has to have the following fields filename and optionally fileattribs, filesize.
If the fileattribs field is present rows with the attribute FILE_ATTRIBUTE_DIRECTORY are skipped.
If the filesize field is present rows with a size of 0 are filtered out.
The filename field has to be a full path to the files.
If the source cursor is to be created by the ADIREX function, specify the ADIREX_FULLPATH option.

cnResult

The alias or workarea number of the result cursor.

If an alias is passed a result cursor according to the specified nMode and cContextField is created.

When passing a workarea number the result cursor is reused and results are just appended.

cContextField

An additional field definition to add to the result cursor, e.g. "fileid I NOT NULL".

Note

The field has to be present in the cnSource cursor.
If the source cursor was created with ADIREX and the ADIREX_FILEID flag, the fileid field can be passed to uniquely identify
the records in the resulting cursor forming a parent child relationship.

nBufferSize (optional)

In streaming mode this specifies the buffer size in bytes used.
Two buffers of size nBuffersize are used alternativly to execute the hyperscan operation.

If omitted the default buffer size in streaming mode is dependant an the supplied scan horizon passed in the nMode parameter.
HS_MODE_SOM_HORIZON_SMALL = 64 Kb
HS_MODE_SOM_HORIZON_MEDIUM or HS_MODE_SOM_HORIZON_LARGE = 256 Kb

Bigger buffers allow more tracking ability when matching large expressions and reduce IO and transition overhead into kernel functions.

Note

If a match can not be fully tracked, it will get truncated and the match_from field in the result cursor is set to -1.


In block mode this specifies a maximum allowed filesize, files bigger than this will be skipped.
This allows to prevent too large memory allocations to occur since one obviously cannot load really large files (multiple gigabytes) into RAM at once.

If ommitted in block mode the default maximum of 16MB is used.

Note

If the nMode flag HS_MODE_EX_STORE_SKIPPED is passed in block mode
one record for any file that is bigger then the supplied buffersize is stored in the result cursor.
The record will have a match_id of -1 and match_from and match_to of 0 to indicate this condition.

Return Value

A hyperscan return code.
HS_SUCCESS (0) on success otherwise the errorcode.
